# NFR-NNNN. Short title, naming the attribute (e.g. "API responses under 200ms p95")

## Status

Proposed | Accepted | Implemented | Rejected | Superseded by [NFR-NNNN](NFR-NNNN-short-title.md)

## Attribute

Which quality attribute this constrains (performance, security,
availability, scalability, usability, maintainability, etc.).

## Description

The constraint itself, stated with a measurable target where possible
("95% of requests to `/heroes` complete in under 200ms under N
concurrent users"), not as a design or implementation detail.

## Source

Which stakeholder(s) (`../stakeholders.md`) or business need drove
this requirement, and any ADR (`../adrs/NNNN-....md`) it prompted or
depends on.

## Verification

How this gets checked — a load test, a security scan, a manual audit —
and how often.
